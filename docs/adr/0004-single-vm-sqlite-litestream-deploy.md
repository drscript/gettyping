# Deploy as a single Fly.io VM with a volume, streamed by Litestream

GetTyping runs as one Fly.io VM with a persistent volume holding the SQLite file, and Litestream continuously streams that file to object storage for backup and disaster recovery. We picked this over a managed multi-writer database because nothing in the spec requires horizontal scale or multi-region writes, and the read-heavy Leaderboard workload is served from the same file a single writer already owns. The trade-off: the app can only ever run as many machines as can share one volume, which for SQLite is one — and a deploy must never recreate that volume or its file, since the `attempt_tokens` table depends on surviving a release to keep a Player's in-flight Attempt alive. If write volume or a genuine multi-region need ever shows up, **Turso** is the documented upgrade path — same SQLite dialect, drizzle schema unchanged — but that migration is out of scope until the need is real.
